# Synthetic COBOL corpus

Small, controlled batch programs written for cobalt. Each one targets COBOL
semantics that a migration must get exactly right.

| Program | Kind | Files | Semantics exercised |
|---|---|---|---|
| `CUSTRPT` | main | CUSTIN → RPTOUT | control breaks, 88-levels, edited PICs (`-Z,ZZZ,ZZ9.99`), COMP-3 totals, SIGN LEADING SEPARATE |
| `INTCALC` | main | ACCTIN → INTOUT | static `CALL`, REDEFINES on dates, `ON SIZE ERROR`, multiple 01s per FD (detail + trailer) |
| `RATECALC` | subprogram | — | LINKAGE SECTION, tiered `EVALUATE`, `COMPUTE ROUNDED` with division (intermediate precision) |
| `TXNPOST` | main | ACCTIN + TXNIN → ACCTNEW + TXNERR + SYSOUT | balance-line match/merge with HIGH-VALUES, `ON SIZE ERROR` on ADD/SUBTRACT, DISPLAY control totals |
| `PAYROLL` | main | PAYIN → PAYRPT | REDEFINES record variants, overtime, ROUNDED vs deliberate truncation, `$` floating and `CR` editing, hash-total control check |

Layout:

```
src/        programs (fixed format: cols 1-6 sequence, 7 indicator, 8-72 code)
copybooks/  CUSTREC, ACCTREC, TXNREC, PAYREC
data/       generated input files (LINE SEQUENTIAL, fixed-width records)
runs.toml   how to compile and run each main program
```

The data files are generated by `scripts/gen_synthetic_data.py` with a fixed
seed and include hand-picked edge cases (tier boundaries, max/min values,
overflow, overdrafts, orphan transactions, invalid codes, closed accounts,
exactly-40-hour weeks, negative net pay). Regenerate with `make data`; never
edit the `.dat` files by hand.
